# kb-tools 開発ガバナンス

**この文書はリポジトリの最高位ルール。GOAL.md よりも優先する。**

## 1. 基本原則

1. **完全非公開 (private)**
   このリポジトリは完全なプライベート。
   コードもドキュメントも一切 **外部公開しない**。

2. **外部共有ゼロ**
   「コード一片」「機能一片」ともに外部に見せない。
   スクリーンショット・GIF・動画・blog 記事・SNS 投稿・発表資料 — すべて禁止。

3. **公開チャネルなし**
   PyPI 公開、コンテナレジストリ push、docs サイトの公開、package manager への登録 — すべて行わない。
   インストールは `git clone` + `pip install -e ".[dev]"` のみ。

4. **公開 release フローを保持しない**
   release.yml のような PyPI 公開用ワークフローは存在しない。
   タグ push で自動 publish される経路は作らない。

5. **計画経由のみ**
   新機能の追加は `docs/GOAL.md` の「現在の標的」に書かれているものに限定する。
   書かれていない機能を作ってはいけない。

6. **AI エージェントへの指示**
   外部共有は jinno が明示的に指示しない限り行わない。
   「便利そう」「外部に見せたら喜ぶかも」の独断で共有しない。

## 2. なぜこのルールか

このプロジェクトは **自己強化型ナレッジ管理システム**。
技術そのものに新規性は少なく、価値の本質は次の 3 つ:

- 現実の corpus を持ち、運用している
- フィードバックループ（`kb sft → kb evaluate → kb improve`）を実際に回している
- その過程で蓄積された履歴（どのモデルがいつなぜ採用されたか）を持っている

情報が漏れた場合、ツール自体（コード）は **1 日以内に clone して同等品を作れる**。
corpus の中身や運用履歴だけが差別化の源。
corpus を守るために、ツールのコードも完全非公開にする。

## 3. 適用範囲

| 対象 | ルール |
|---|---|
| リポジトリ (GitHub) | **private**。jinno のみがオーナー。共同開発者を追加する場合は明示的に許可する |
| Issue / PR | **private** リポジトリ内でのみ。外部公開フォーラムへの転載禁止 |
| Documentation | `docs/*.md` はリポ内のみ。docs サイト公開禁止 |
| 配布 | しない。`git clone` 経由のみ |
| 発表・登壇・blog | 一切禁止 |
| スクリーンショット | 公開チャット / メール / SNS に貼らない |
| AI エージェントへの文脈共有 | このリポの内容を他のツール / 別リポ / 公開 prompt に持ち込まない |

## 4. 例外

jinno が明示的に「これは共有 OK」と指示した場合のみ例外を認める。
例外を認める場合は **いつ / 何を / 誰に / どのチャネルで** をメモする。

## 5. 違反が疑われる場合の対応

1. 即座に共有を停止
2. 共有内容を revert または削除
3. 違反の発生源（commit / PR / AI セッション / スクリプト）を特定
4. `docs/MEMO.txt` にインシデント記録を残す
5. 再発防止を GOVERNANCE.md に追記

## 6. 関連ドキュメント

- `CLAUDE.md` — AI エージェント（Claude Code）がこのルールを毎セッション読むための入口
- `docs/GOAL.md` — 何を達成しようとしているか（WHAT）。本書は HOW の上位制約
- `docs/FEEDBACK_LOOP.md` — フィードバックループのプレイブック
- `docs/MEMO.txt` — セッション横断の共有ノート。インシデント記録もここ

## 7. この文書の変更

この文書自体の変更には jinno の明示的承認が必要。
変更したら `docs/CHANGELOG_GOVERNANCE.md` に変更履歴を追記する（任意）。
変更は「緩める」方向（「共有して OK な対象を追加」など）でも、理由を必ず併記する。
